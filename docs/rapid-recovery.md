# Candidate generation first

This register-state candidate factory is paused during the transition to the
[native x86 C++ and reccmp loop](reccmp-loop.md). Retained proposals remain
available; do not resume dispatch with the old ABI merely to increase counts.

`rapid/` is an independent candidate factory. It reads actual pinned executable
bytes and the existing static function inventory, and stores DeepSeek C++ proposals
under ignored `local/rapid/`. Every result is **unvalidated**. Syntax compilation
only establishes that a compiler accepts the proposal with the shared guest ABI.
It changes no recovery registry, contract, oracle, corpus or acceptance criteria.
Equivalence checking is a separate downstream operation. The only authored artifact
per function is its C++; no contract, fixture, test corpus, custom wrapper or proof
annotation is required. Byte packets, identity records and compiler products are
generated by common machinery. See [automatic checking](automatic-checking.md) for
the revised checking direction; no new semantic checker is running yet.

The shared [ABI and schemas](../rapid/INTERFACE.md) define one guest Context
entrypoint for every RVA. Packets pin the executable, exact range bytes, header,
inventory and request. Function boundaries, signatures and direct callgraph edges
remain static hypotheses. Overlapping, discontiguous, undecodable, nonexecutable
and initially oversized ranges are explicitly delayed in preparation.json. Startup
breadth is prioritized; related callees and adjacent inventory groups fill bounded
packets (20 functions maximum and 40,000 serialized packet bytes). A conservative
output heuristic also caps each group at 20,000 estimated tokens: 500/function
plus 80/decoded instruction. This estimate is a scheduling heuristic, not a promise
about provider output. Single functions above these limits are explicitly delayed
as needs_larger_budget. The initial two paid pilot packets are retained unchanged;
a measured truncation motivated repartitioning only never-dispatched queue entries. Large bodies
remain graph traversal nodes. Resolved calls execute through an explicit resolver;
missing semantics throw Unsupported and never return a successful dummy value.
Candidates may contain acknowledged unsupported paths and are still unvalidated.

From the repository root, using a Python with pefile and Capstone:

```sh
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid prepare --max-groups 300
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid run --pilot
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid run
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid status
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid pause
/Users/daeken/projects/DAODecomp/.venv/bin/python -m rapid pause --resume
```

The pilot dispatches exactly two batches and exits after both finish. Start the
continuous run after checking the retained pilot outputs. `--root`, `--main`,
`--global-db`, and `--ledger` are global options placed before the subcommand;
defaults identify this worktree and the preexisting shared budget ledgers.
Additional prepare calls deduplicate already queued function RVAs. The runtime
keeps one owner flock and at most two independent provider processes. Pause stops
new dispatch; existing calls finish and save their bounded responses. SIGTERM/SIGINT
also request a graceful pause. Resume clears the flag; `run` clears pause at startup.
An interrupted claimed batch with no completed final record becomes
interrupted_unknown on restart and is never automatically replayed. All request
slots and daily reservations remain charged if their outcome is uncertain.

The authoritative existing request database is reused append-only: no old tasks,
claims, cycle anchors or accounting entries are reset. Each paid request reserves
one of 12 requests per persisted 1800-second cycle (24/hour across this workflow
and the old runtime). A full cycle waits without provider calls. Every actual
provider attempt separately reserves the existing $50/calendar-day America/Chicago
ledger using workers.deepseek_packet.Ledger, with its unchanged credential-scanning
transport, endpoint api.deepseek.com, model deepseek-flash, and reasoning low.
No automatic retries or model-driven repair requests are issued. The key is read
only in the bounded request process and never logged or copied into artifacts.
Raw responses, including malformed or truncated proposals, are retained after the
existing transport's credential scan. Costs are provider usage estimates or
conservative unknown-outcome reservations, not invoices.

queue.sqlite3 contains durable pending/claimed/complete/error/interrupted_unknown
batches and unique per-function ownership. Preparation may additionally record
needs_larger_budget and superseded_undispatched dispositions; neither represents
a provider success or behavioral result. A complete batch means its response
schema was accepted; it never means behavioral recovery. status.json reports
proposed and syntax-accepted function counts, zero verified functions, charged
cost, token usage, latency, queue state and active processes. Successful source
bytes are content-addressed under objects/. Each result points to its exact
content-addressed ABI snapshot under abi/. Batch folders retain actual requests,
packets, raw responses, structured responses, candidate source, compiler diagnostics
and hash-bound result metadata. The original binary and its assets remain in the
existing ignored original install and are only read during static preparation.
